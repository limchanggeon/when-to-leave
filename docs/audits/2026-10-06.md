| 항목 | 이전 | 수정 후 |

| 터미널 목록의 부팅 실패 | 빈 목록이 프로세스 수명 동안 고정 | 다음 검색에서 재조회, 회복된 목록으로 후보 검사 |

이전 커밋을 임시 디렉터리에 풀어 새 회귀 테스트를 실행했다. 4개 파일의 9개 테스트 중
6개가 실패했고, 수정본에서는 모두 통과했다. 버스 호출 수/POST 반복/본문 제한/도보
캐시/터미널 회복을 포함한다. 측정은 모의 API에서 이루어졌으며 운영 경로의 실제
검색 지연시간이 95% 감소했다는 뜻은 아니다.

의존성은 proxy-addr/qs/source-map-js/brace-expansion/uuid의 패치 버전과 Vitest 4.1.11로
갱신했다. 공개 권고: [proxy-addr](https://github.com/advisories/GHSA-jqcg-44mw-7w3h),
[qs](https://github.com/advisories/GHSA-4mjr-xmp4-gh2g),
[Vitest](https://github.com/advisories/GHSA-82fw-gwwq-j7x9).
권고의 존재가 현재 설정에서 실제 공격이 재현됐다는 의미는 아니다.

## 운영 경계

기존 EC2/도메인/Caddy/SQLite와 자격증명을 사용한다. 새로운 AWS 자원은 생성하지 않는다.
DB 스키마 변경은 없다. 배포 전 기존 백업 서비스를 실행하고, Node 22 환경의
별도 worktree에서 타입 검사/테스트/빌드/HTTP 검사를 다시 수행한다.
서비스 교체 때 짧은 중단은 발생할 수 있다. 교체 실패 시 기존 코드·dist·node_modules를
복구하며, 실제 데이터가 바뀌지 않는 이번 릴리즈에서는 DB를 자동 덮어쓰지 않는다.

외부 제공자의 시간표 정확성/좌석 정보, 실메일 수신, 실사용자 소셜 로그인·캘린더 쓰기,
실기기 GPS/알람, S3 백업의 실제 복원은 이 검사로 검증되지 않는다.
CI 파이프라인은 구성되어 있지 않아 로컬 및 EC2에서 직접 검증한다.

AWS 배포 결과와 운영 커밋은 배포 후 이 문서에 기록한다.
