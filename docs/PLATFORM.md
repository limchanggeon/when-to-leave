# 플랫폼 전략

웹 먼저, 이후 Android·iOS 앱. 나중에 다시 짜지 않으려고 지금부터 레이어를 가른다.

## 규칙

`src/engine`, `src/adapters`, `src/parse`, `src/i18n` 은 **React도 DOM도 모른다.**
`Date`, `fetch`, 순수 함수만 쓴다. `window`, `document`, `localStorage`를 직접 참조하지 않는다 —
저장이 필요하면 이 레이어는 인터페이스만 받고, 구현은 `src/ui`(웹) 또는 앱 쉘(RN)이 주입한다.

이 규칙이 지켜지면 위 네 폴더는 웹 빌드와 React Native 빌드 양쪽에서 **그대로** 재사용된다.
다시 짜야 하는 건 `src/ui` 뿐이다 — 화면은 어차피 플랫폼마다 다르게 그려야 한다.

## 지금 결정: 웹은 React + Vite

앱 전환 시점에 고른다. 후보 두 갈래:

| 경로 | 장점 | 비용 |
|---|---|---|
| **Capacitor** (웹뷰 래핑) | 지금 UI를 거의 그대로 씀. 캘린더·푸시는 네이티브 플러그인으로 보강 | 진짜 네이티브 느낌은 약함 |
| **React Native (+ RN Web)** | 진짜 네이티브 UI, 성능 | `src/ui`를 다시 그려야 함(엔진은 재사용) |

지금 당장 정할 필요는 없다 — 위 규칙만 지키면 어느 쪽을 골라도 손실이 `src/ui` 하나로 한정된다.
CSS는 지금은 일반 CSS를 쓰되, 나중에 RN을 고르면 style 객체로 옮기기 쉽도록
**flex 기반 레이아웃, 색상은 토큰 변수 참조**로 짠다 (grid는 RN 미지원이라 최소화).

## 지금 걸어두는 제약

- 로컬 저장은 `src/ui/storage.ts` 의 인터페이스 뒤에 둔다(웹은 localStorage, 앱은 나중에 SecureStore 등으로 교체).
- 날짜는 항상 `Date` 객체로 다루고 포맷은 `src/engine/time.ts` 에서만 한다 — 플랫폼별 로케일 API에 흩뿌리지 않는다.


## TAGO (공공데이터포털) — 찔러보고 알아낸 것

문서와 실제가 자주 어긋난다. 아래는 전부 실제 호출로 확인한 값이다.

### 오퍼레이션 대소문자가 서비스마다 다르다

가장 많이 시간을 버린 함정. 틀리면 키 문제처럼 보이는
`[12] 해당 오픈API 서비스가 없거나 폐기됨` 이 온다.

| 서비스 | 첫 글자 | 예 |
|---|---|---|
| TrainInfo · ExpBusInfo · SuburbsBusInfo · SubwayInfo · DmstcFlightNvgInfo | **대문자** | `GetStrtpntAlocFndTrainInfo` |
| ArvlInfoInqireService · BusLcInfoInqireService | **소문자** | `getSttnAcctoArvlPrearngeInfoList` |

### 그 밖의 함정

- **시외버스 터미널 목록은 `GetSuberbsBusTrminlList`** 다.
  도시별(`GetCtyAcctoSuberbsBusTrminlList`)은 존재하지 않는다.
- **터미널 코드 체계가 고속과 시외가 다르다.** 고속은 `NAEK300`,
  시외는 `NAI3455101`. 같은 "대전복합" 이라도 서로 못 쓴다.
- **시각 자릿수가 다르다.** 고속버스·항공은 12자리(`202609040600`),
  시외버스는 14자리(`20260904063000`). 앞 12자리만 쓰면 둘 다 맞는다.
- **지하철에는 노선의 역 순서를 주는 API 가 없다**(오퍼레이션이 4개뿐).
  대신 역 ID 에 순번이 들어 있다 — 강남 `MTRS12222`, 역삼 `2221`,
  삼성 `2219`. 종점 ID 가 목적지와 같은 쪽인 방향을 고르면 상·하행이 갈린다.
- **지하철 dailyTypeCode 는 01(평일)/02(토)/03(일·공휴일)** 이고,
  **02 가 비어 있는 노선이 있다.** 하루가 비었다고 전체를 버리면 안 된다.
- **키 하나가 모든 서비스를 열지 않는다.** 서비스마다 따로 신청해야 하고,
  미신청이면 `[30] 등록되지 않은 서비스키` 가 온다.

### 아직 못 붙인 것

- **버스도착정보**(`ArvlInfoInqireService`)는 동작하지만 `nodeId` 가 필요하다.
  좌표로 정류소를 찾아주는 **정류소정보**(`BusSttnInfoInqireService`)가
  미신청이라 ODsay 의 정류장과 이어붙일 수 없다.
- **버스위치정보**(`BusLcInfoInqireService`)는 `routeId` 가 필요하고,
  그것을 주는 **노선정보**(`BusRouteInfoInqireService`)도 미신청이다.


## 경로 제공자를 ODsay 에서 카카오+TAGO 로 바꾼 이유 (2026-09)

ODsay 는 길찾기를 통째로 해주지만 무료 한도가 작고, **도보 구간의 선형을
주지 않아** 지도가 산을 가로지르는 직선을 그렸다.

2026-07-21 에 카카오가 대중교통·도보 경로 API 를 열었다(일 1,000건 무료).
모든 구간의 실제 좌표를 도보까지 함께 주고, 선형이 같은 응답에 들어 있어
추가 호출도 없다. 다만 **시외는 못 한다** — 대전역→부산역은 NO_RESULTS 다.

그래서 이렇게 나눴다:

| 구간 | 담당 |
|---|---|
| 시내 대중교통 | 카카오 `v2/routing/publictraffic` |
| 정류장까지 도보 | 카카오 `v2/routing/walk` |
| 시외(열차·고속·시외버스·항공) | TAGO 시각표 + 우리가 조합 |
| 허브(역·터미널) 찾기 | 카카오 장소 검색 |
| 허브(공항) 찾기 | TAGO 공항 목록 + 지오코딩 |

### 조합하며 밟은 함정

- **먼 거리에도 카카오는 "성공" 을 돌려준다.** 대전→서울에 광역버스를 엮어
  3시간짜리 경로를 준다. 카카오가 실패할 때만 시외를 보면 KTX 가 영영 안 나온다.
  40km 이상이면 두 방법을 **다 돌려** 합친다.
- **허브 필터는 카테고리만 보면 안 된다.** "흑석리화물역" 은 카테고리가 그냥
  "기차역" 이라 통과한다. 이름까지 봐야 폐역·화물역·신호장이 걸러진다.
- **공항은 장소 검색으로 못 찾는다.** "공항" 으로 서울역 근처를 뒤지면
  공항철도역과 도심공항터미널이 앞을 다 차지한다. TAGO 공항 목록(15곳)을
  지오코딩해 두고 가까운 곳을 고른다.
- **터미널 이름의 꼬리말 처리가 미묘하다.** "대전복합터미널"→"대전복합"(유지),
  "부산종합버스터미널"→"부산"(제거). "복합" 은 이름의 일부고 "종합버스" 는 꼬리말이다.

## 메일 (2026-09)

인증 메일은 SES(서울)로 보낸다. SDK 를 넣지 않고 SigV4 로 직접 서명해
HTTPS 로 부른다 — 필요한 건 해시와 HMAC 뿐이라 node:crypto 로 충분하고,
메일 한 통 보내자고 `@aws-sdk/client-sesv2` 를 끌어올 이유가 없다.

서명 구현(`server/sigv4.ts`)은 **AWS 가 공개한 시험 벡터(get-vanilla)로
검증한다.** 자격증명 없이 이걸 확인할 수 있는 유일한 방법이라, 그 벡터를
그대로 재현하도록 맞춰뒀다 — 그래서 S3 가 요구하는 `x-amz-content-sha256`
헤더는 넣지 않는다(SES 는 필요로 하지 않고, 넣으면 벡터가 안 맞는다).

발송 실패는 **던지지 않고 값으로 돌려준다.** 메일이 안 나갔다고 가입 자체를
깨뜨리면 잠깐의 SES 장애가 서비스를 멈추는 셈이 된다. 못 보냈으면 로그에
남기고, 사용자는 "다시 보내기" 로 되돌아온다.

전송기가 `console` 이면 메일이 로그에만 찍힌다. 운영에서 그 상태면
`/api/health` 의 `missingEnv` 가 알려준다 — 조용히 사라지는 게 제일 나쁘다.

## 인증·비밀번호 (2026-09)

**진짜 방어는 시도 횟수 제한에 있다.** 비밀번호 규칙을 아무리 조여도 무한히
찔러볼 수 있으면 결국 뚫리고, 반대로 제한이 있으면 8자짜리도 현실적인 시간
안에는 못 맞힌다. 그래서 규칙은 최소한만 두고(NIST 800-63B) 제한을 건다.

- **복잡도 규칙을 두지 않는다.** 특수문자·대문자 필수는 사람들을
  `Password1!` 같은 뻔한 모양으로 몰아서 실제 안전성이 거의 안 오른다.
  대신 길이와 **뻔한 모양**(흔한 것, 연속·반복, 이메일에서 딴 것)을 본다.
- **특수문자·공백·한글을 막지 않는다.** 모든 질의가 준비된 문(`?`)을 쓰므로
  따옴표가 섞여도 안전하고, 오히려 못 쓰게 하면 선택지가 줄어 약해진다.
- **상한이 있다(128자).** 없으면 아주 긴 입력으로 scrypt 를 돌려 CPU 를
  태울 수 있다. 일부러 비싼 함수라 그게 그대로 공격이 된다.
- **scrypt 계수를 저장값에 적는다**(`scrypt$N$r$p$salt$hash`). 예전에는
  안 적어서 계수를 올리면 기존 해시를 못 읽었다. 지금은 옛 형식도 읽고,
  로그인에 성공하면 그 자리에서 새 계수로 다시 저장한다 — 평문을 손에 쥐고
  있는 유일한 순간이라 놓치면 영영 못 올린다.
- **없는 계정도 같은 시간을 쓴다.** 문구만 같게 하면 응답 시간이 가입 여부를
  알려준다. 계정을 못 찾아도 같은 무게의 해싱을 한 번 돌린다.
- **가입은 형식 검사를 통과한 시도만 센다.** 앞에 두면 비밀번호를 몇 번
  잘못 적은 사람이 한 시간 잠긴다. 세는 자리는 "이미 가입된 이메일입니다"를
  돌려주는 지점 — 거기가 이메일을 훑을 수 있는 자리다.

시도 횟수는 **프로세스 메모리**에 있다. 서버가 하나뿐이라 충분하고,
재시작하면 풀린다. 서버를 늘리면 여기부터 손봐야 한다.

## 시각 언어 — "발차 안내판" (2026-09)

역 대합실 전광판에서 가져왔다. 어두운 인디고 판 위 호박색 숫자.

- **판은 하나이고, 자르지 않는다.** 머리·바로가기 줄·답·질의가 전부 같은
  어두운 판 위에 있고 가로 괘선으로만 나뉜다. 예전에는 이 판 위에 흰 카드를
  띄워 검색을 담았는데, 그러면 판이 반으로 잘리고 어느 SaaS 홈이나 같은
  모양이 된다. 지금은 **검색도 판에 새긴 한 줄**이다 — 입력은 채워 넣은
  상자가 아니라 밑줄 그은 빈칸이다.
- **판에는 늘 답이 걸린다.** 아직 물어보지 않았으면 **불이 꺼진 자릿수**
  (`88:88`)가 걸려 있다. 다음 차가 정해지기 전의 전광판이 그 모습이라,
  소개 문장 한 줄 없이도 이 자리가 무엇을 위한 자리인지 알 수 있다.
  꺼진 자릿수와 답은 **글자 크기·굵기·자간이 같아야 한다** — 답이 들어올 때
  자리가 밀리지 않고 그 자리에 그대로 불이 들어와야 하기 때문이다.
- **화면에서 제일 큰 것은 언제나 시각이다.** 날짜("내일")는 딱지로 떼어
  옆에 붙인다. 호박색 숫자 안에 한글이 섞이면 제일 커야 할 것이 시각이
  아니라 문장이 된다.
- **안내판 한 줄의 모양을 따른다.** 왼쪽에 시각, 오른쪽 끝에 상태
  (남은 시간). 열 머리말은 괘선을 사이에 두고 왼쪽에 이름, 오른쪽에 지금 상태.
- **상자를 늘어놓지 않는다.** 같은 라운드·같은 그림자 카드를 나열하면
  무엇이 중요한지 사라진다. 머리말과 선으로 구역을 나눈다.
- **호박색은 "지금 중요한 것" 에만 켠다** — 답이 된 시각, 주 동작
  (계산하기·로그인), 지금 켜져 있는 것(고른 탭·고른 시각·초점 든 칸).
  마우스가 스쳤다는 이유로는 켜지 않는다. hover 는 흰색으로 답한다.
- **반경은 계단이 있다.** 판과 판 위의 것은 각지고(2–4px), 밝은 종이 위에
  담는 것만 살짝 둥글다(6px). 알약(999px)은 정말 둥근 것에만 — 아바타,
  그리고 자기 가이드를 따라야 하는 카카오·구글 버튼.
- **판 위에도 선이 둘이다.** 장식 괘선은 `--night-rule`(0.14), **누를 수 있는
  것의 테두리**는 `--night-edge`(0.36 — 판 대비 3.3:1). 후자가 그 요소의
  유일한 경계라 3:1 을 넘겨야 한다.
- 숫자는 전부 `.num`(Archivo, tabular-nums)을 탄다. 자릿수가 흔들리면
  시각표가 무너진다.
- `word-break: keep-all` — 없으면 한글이 "계산합 / 니다" 로 잘린다.
- **연출하는 순간은 둘뿐이다.** 계산하는 동안 꺼진 자릿수가 깜빡이고
  (`warmup`), 답이 판에 걸릴 때 한 번 올라온다(`rise`). 카운트다운 고리는
  90분 안쪽에서만 그린다 — 18시간짜리 꽉 찬 고리는 진행 표시가 아니라
  그냥 동그라미다.

사용법은 **살아 있는 화면을 짚어준다**(헤더의 물음표). 어두운 덮개에 구멍을
뚫어 지금 해야 할 자리를 비추고, 그 칸에 값을 넣으면 저절로 다음 걸음으로
넘어간다. 덮개는 클릭을 막지 않는다 — 막으면 짚어준 칸에 글자를 못 넣어
안내가 아니라 방해가 된다.

한동안 화면 캡처를 넘겨 보여줬는데(슬라이드 온보딩) 두 가지가 걸렸다.
화면을 고칠 때마다 캡처가 낡았고, 보는 사람은 아무것도 하지 않았다.
홈에 예시 칩을 늘어놓지 않는 것도 같은 이유다 — 매일 쓰는 도구의 첫 화면을
설명이 차지하면 정작 쓰는 자리가 밀린다.

의도적으로 피한 것(생성형 UI 의 흔한 티): 제목 위 대문자 eyebrow 라벨,
가운뎃점으로 이은 메타 문자열, 전부 같은 반경·같은 그림자의 카드 키트,
범용 SaaS 파랑, 어두운 히어로 위에 띄운 흰 라운드 카드, 모든 것을 알약으로
만드는 반경, 소개 페이지마다 있는 01/02/03 번호 딱지, 갈래로 묶은 다단 푸터.
